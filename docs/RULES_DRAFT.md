# Tactical Go Lite — P0 規則凍結（Draft v0.2）

> 狀態：**Draft**。以下每一條都是為了讓引擎可測試而做的暫定決定，Owner 試玩後才能升為 Accepted。
> 凡是 PLAN 沒明說、由實作者補上的決定，標記為 `【補】`，請 Owner 優先審視；第 8 節列出每一項的審核狀態。
> v0.2（2026-10-08）依 Owner 決定修改：英雄不可重召、召喚改為鄰接任一己方棋子、先手首回合 1 AP 設為預設。
> 對應程式：`src/TacticalGo.Domain`；對應測試：`tests/TacticalGo.Domain.Tests`。

## 1. 盤面與單位

- 9×9，座標 `(X, Y)`，`X` 向右、`Y` 向下，皆 0–8。可由 `RuleConfig` 改尺寸。
- 單位三種：主將 Commander、英雄 Hero、士兵 Soldier。
- 初始：玩家一主將 `(4,7)`，玩家二主將 `(4,1)`（上下對稱）。`【補】`
- **棋串**：同一玩家的任何單位（主將／英雄／士兵）以四方向正交相連，視為同一棋串，共用氣。
- **氣**：棋串四周的空點（含被封印的空點，封印不影響氣）。

## 2. 回合與資源

- 玩家一先手。每回合 AP = 2（`RuleConfig.ApPerTurn`）；落子、召喚、施法各 1 AP；可 `EndTurn` 提前結束，剩餘 AP 作廢。AP 用完自動結束回合。
- Mana：初始 3；**每位玩家每個回合開始 +1，上限 6**。首回合也會 +1（所以玩家一第一回合有 4）。`【補】` — Owner 暫時接受（雙方對稱），觀察是否讓技能太早爆發。
- **先手首回合 1 AP（暫定預設，2026-10-08 Owner 決定）**：玩家一第一回合只有 1 AP，之後所有回合 2 AP。`RuleConfig.FirstTurnAp = 1`。
  原始「首回合也是 2 AP」保留為比較基線：`RuleConfig.TwoApBaseline`。依據見 `docs/S0_AP_GATE.md`（啟發式機器人探針，**不是**最終平衡驗收）。
- 每方每回合最多施放一次技能。

## 3. 原子行動與結算順序（每個行動都照此順序）

1. **Validate**：基本條件（遊戲進行中、AP、Mana、目標、範圍、封印、職業）。
2. **Apply（在複本上）**：把整個行動的所有盤面變更一次套到盤面複本。
3. **Resolve captures（立即提子）**：先移除「對手」所有無氣棋串；再檢查「行動者」是否仍有無氣棋串 → 有則為**自殺著，整個行動非法**。
4. **Ko 檢查**：結果盤面不得與歷史上任何盤面相同（positional superko，不分輪到誰；歷史含初始盤面）。
5. **Commit**：全部通過才扣 AP／Mana、改盤面、記歷史、發事件。任何一步失敗 → 狀態**完全不變**、不扣資源、不發事件。
6. 若對手主將被提 → 行動者**立即獲勝**。否則 AP = 0 則自動換手。

提子是「每個原子行動後立即結算」，與回合末提子不並存。

- 因為提子在結算時才發生，**自殺著可被同一行動的提子救活**（標準圍棋）。例如戰士築壘兩子同時落下，其中一子單獨看是自殺，但兩子合併後有氣，合法。
- 勝負判定先於自殺判定不成立：自殺著一律非法，所以不可能發生「行動者主將被自己提掉」。

## 4. 召喚與英雄

- 每方場上最多一名英雄；職業在開局選定（`None` = 無職業對照組，不能召喚、不能施法）。
- 召喚：1 AP + Mana（戰士 2 / 法師 3 / 盜賊 2）；位置為**空點、與任一己方棋子（主將／英雄／士兵）上下左右相鄰、未被對手封印**，並服從自殺／Ko 規則。（Owner 決定；取代 v2.0「必須接氣」與先前草稿的「主將兩格內」。理由：主將不能移動，兩格限制會把英雄困在角落，鄰接任一己方棋子讓戰線推進、也讓部署位置成為決策。）
- 英雄被提後從盤面消失，不能施法，且**第一版不得重新召喚**（`RuleConfig.AllowResummon = false`，Owner 決定，讓英雄死亡有真實代價）。`AllowResummon = true` 只留作對照實驗。

## 5. 三個招牌技能（皆 1 AP + 2 Mana，施法者英雄必須在盤上）

| 技能 | 合法目標 | 效果 |
|---|---|---|
| 築壘（戰士） | 戰士英雄四方向相鄰的**兩個不同空點**，皆未被封印 | 同一原子行動放兩顆己方士兵，再結算 |
| 魔法之手（法師，預設） | 距法師曼哈頓 ≤2 的一顆**雙方普通士兵** | 推至玩家所選正交方向的相鄰空點，保留歸屬，再結算；雙方主將／英雄禁推 |
| 封印（法師，比較基線） | 距法師曼哈頓 1–2 的一個**空點**，且尚未被封印 | 對手在其**下一個回合**不能在該點放置任何單位；敵方回合結束即解除；該點仍是空點、仍算氣 |
| 換位（盜賊） | 盜賊英雄四方向相鄰的一顆**敵方士兵**（不含主將／英雄） | 兩者互換位置，再結算（盜賊落到對方位置可能提子；若自己因此無氣則整個行動非法） |

封印只限制「放置」（落子／召喚／築壘）；不影響提子、換位（換位不會把子放到空點）。

### 魔法之手預設與封印比較版本（2026-10-08 Owner 最新決定）

- `RuleConfig.MageSkill` 預設是 `MageSkill.MagicHand`；明確指定 `MageSkill.Seal` 可切回封印比較基線。每個版本各只提供所選法師技能，不能同時使用兩種。
- 法師在場、技能本回合未用、至少 1 AP 與 2 Mana；選一顆距法師曼哈頓距離 ≤2 的**雙方普通士兵**，再選上／右／下／左。Owner 本輪明確核准己方士兵，不含己方英雄或主將。
- 目標移至該方向的相鄰空點，保留棋子歸屬；目的地須在棋盤內。不能推雙方主將、英雄、佔據點、棋盤外，不能連鎖推動。法師留在原地。
- 費用是 1 AP＋2 Mana，每回合最多一次技能；仍使用 §3 的自殺、positional superko 與原子回滾流程。成功事件順序為扣資源、`PiecePushed`、必要的提子／勝負／換手事件。
- **幾何更正**：敵兵從 A 移到正交相鄰空點 B，A 變空，必然是 B 所在敵方棋串的一口氣。因此「單次推動使該敵兵零氣被提」不可作為可達成測資；不新增特殊處決規則。後續落子堵住 A 可在特定棋形完成提子。
- 己方被推士兵同樣保留 A 這口氣；將己方兵移入另一敵方棋串的最後一口氣，則可能按既有提子流程當次提掉敵子。這不是對被推目標新增處決效果。
- 本輪 Owner 核准切換 Domain 預設，不接 UI；現有 UI 分支／exe 尚未整合，G3 未開工。既有封印搜尋的 476 局面零獨有勝局、且防守面未涵蓋，是交接中的歷史結果，本輪不重跑也不補跑。
- 驗證與限制見 `docs/R1_MAGIC_HAND.md`；測試通過與有限棋形不代表職業平衡、好玩或可進 G3 UI。

## 6. 勝負

- 提吃敵方主將 → 立即獲勝。
- 達 `MaxPlies`（預設 100，即雙方各 50 回合）仍無人被斬首 → **和局**（不冒稱地盤計分）。
- 沒有「連續 Pass 終局」規則；Pass 只是提前結束回合，因此由 `MaxPlies` 保證終止。

## 7. 暫不實作（與 PLAN 一致）

永久虛擬氣、紅龍、神器／卷軸、DC 骰子、兩條命、隕石、時間扭曲、煙霧彈、職業被動、地盤計分。
