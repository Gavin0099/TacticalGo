| 行動模式 | 放士兵、召喚英雄、現有普通技能 | 目前模式金色；法師選士兵後此列暫換方向，保持控制區高度 |

一般局面展示盜賊：原技能有合法換位目標，但目前選的是普通落子。技能預覽展示法師：把白兵 E4→E3（9×9 為 F5→F4），無提子；頂部仍 2 AP／Mana 5，說明確認後 1 AP／Mana 3。主將危險展示戰士：主將棋串只有 1 氣 D7（9×9 E8）；普通落子延伸該氣确实合法，提示只對此示例成立，不在正式 UI 硬編碼救命坐標。

這三個固定局面不是同一局的連續棋譜，也不宣稱歷史可達。所有既有棋群有氣；兩種尺寸的預覽事件、资源與完整復原由 exporter 的 assertion 檢查。

## 視覺與素材接線

原圖沿用 `ios/TacticalGo/Assets.xcassets/{warrior,mage,rogue}.imageset/portrait.png` 與 `token-{class}.imageset/token.png`；复制 bytes 相同，没有重新生成、重描、換臉或使用示意圖替代人物。材質與板面 SVG 是**布局占位**，不是對另一 Agent 美術的驗收或取代。

黑方底座深藍灰／白色細框；白方底座象牙白／深色細框。主將和英雄保留黑／白字牌，不能只依金冠或角色服裝判斷。人物 B 卡不縮成棋盤英雄；A Token 才是棋盤圖像。

| 圖層（後→前） | 規格 |
|---|---|
| 棋盤厚度／陰影 | 深棕底板下移7 px，柔和投影；木面、暖金邊框、低對比木紋 |
| 棋盤格線／棋點 | 格線固定在交叉點；不讓背景木紋掩蓋氣與坐標 |
| 合法候選 | 普通落子以淡色點，技能士兵候選用薄環；不能覆蓋棋子身份 |
| 陣營底座／棋子 | 陰影→黑白底座→士兵本體或 A Token→主將冠／黑白字牌；按 y 排序 |
| 行動與危險覆蓋 | 選中原位淡化、方向箭頭、目的地半透明白兵与金色虛線；最後一氣紅色虛線、主將危險環 |
| HUD／操作 | 置於棋盤外；确认区域固定，不随选取位置浮动遮盘 |

共享投影：row=y/(N−1)，width=0.74+0.12×row，u=0.5+(x/(N−1)−0.5)×width，v=0.18+0.65×row。基準為純 Swift `BoardProjection`；HTML只是靜態同式畫稿，不接管規則坐標。Token 腳底對齊底座中心，不以頭部中心作命中。

角色与棋盤正式美術接入时应提供透明 A Token／原始 B 卡、無棋子的板面底圖，以及陰影／底座的可分離素材；本文件不要求另一 Agent 已完成這些，也未向其送出新工作指令。Owner 最新附圖用作素材風格參考，其示意棋局不直接当规则 fixture。

## 尺寸與觸控邊界

390×844：主要人物卡完整保留定位、费用与可用性。320×568：縮小人物區並收起次要定位説明，仍保留角色原畫、技能名／費用、回合資源、完整确认與结束回合。假狀態列保留安全區，不畫假電信／電池資料；原生整合須讀取實際 safeAreaInsets，而非照抄 CSS 的38／20 px。

所有主要行動、確認／取消／復原／結束與頂部返回／選單設計框均至少44×44 CSS px。這是稿面檢查，**不等於44 pt真機可點擊驗收**；主將、英雄與普通棋的格點命中仍须在V2原生验证。

7×7 的390稿格距約45 px；390 的9×9約34 px。320稿7×7約28 px、9×9約21 px。不能將全盤小格直接當成舒適觸控目標：V2 必須測試選點後局部放大／候選格確認／既有格點清單，尤其密集棋形與9×9。下一輪不能只加陰影就宣稱操作通過。

更大字級下應允許次要說明捲動／折疊，AP、Mana、目前行動方與確認仍常駐；VoiceOver讀取陣營、棋種、坐標、氣、合法性与預覽差異。這些是原生實作驗證待辦，本輪 HTML 截圖不當作其測試證據。
