# TG12 P1R：盜賊 ply 60 反制與能量取捨

研究範圍固定為 P0 `b9-Priest-Rogue`、zero-based turn 59／ply 60，9×9、盜賊起手 6 能量。P1 基線為 PR #36 `50f505a` 的 16 局面、192 候選；本次只檢查其中六個指定方案，不另挑有利起點。

## 判斷

候選 #5「先落兵、再連鎖換位」的兩顆淨提兵成果，能保留到對手完整回合結束。針對這個固定局面，881 個不同的有序反擊已涵蓋所有現行合法單回合行動：168 個純落兵／提早結束，713 個牧師技能組合。全數淨提兵 +2，盜賊主帥與英雄均存活。這是局部完整的單回合結論，不是長期安全或最佳策略證明。

再延伸雙方各一回合，#5 的五條選定 Standard 續局累計淨提 3–4 兵。原 Bot 與普通兩兵對照的選定續局為 1–2 兵。各分支的續局回應獨立選取，沒有對齊同一敵方策略，也未窮舉第二輪；不能拿這些範圍當 minimax 優勢。

## 提兵、盤上兵力與能量要分開看

`observedNetMaterialRange` 是既有 V1 欄位名稱，實際意義是**淨提兵差**，沒有計入本輪新落兵或牧師自行獻祭。`summary.json` 另計盤上「盜賊士兵數減牧師士兵數」相對起點的變化，避免把提兵差誤當盤面兵力優勢；英雄與主帥不算士兵。

起點盜賊／牧師士兵為 28／32。以下均為各方案的原 Standard 回應，能量包含再次輪到盜賊時恢復的 1 點與上限：

| 方案 | 本輪耗能 | 淨提兵 | 盤上兵數差改善 | 下輪能量 | 下輪連鎖換位實際合法 |
|---|---:|---:|---:|---:|---|
| 原 Bot #0 | 2 | 0 | -1 | 5 | 是 |
| 候選 #5 | 4 | +2 | +1 | 3 | 否 |
| 普通兩兵 #8–11 | 0 | 0 | 0 | 6 | 是 |

這裡確實存在「現在改變棋形、取得提子成果」與「保留下一輪進階技能」的取捨。但無法只用提兵數判定 4 能量值得。五條 #5 續局的盤上兵數差改善為 2–4；普通對照的選定續局也能達 1–4。主帥氣數、英雄位置、盤上兵力與剩餘能量尚未形成可比較的長期勝率。

## 驗證修正與證據邊界

c37e720 的 `rogue-verify` 能核對行動與局面，卻會接受遭改動的摘要：將 #5 回應數改為 0、下輪技能合法性改成 true，仍回報 1,662 次通過。原失敗行為已在本機重現。修正後除重播外，會重算回應／續局指標、核對摘要、拒絕缺失或重複的續局及不完整的第二次敵方回合。

驗證器以不同於產生器的方式，直接遍歷未截斷的 Core 行動樹，比對每個分支的純落兵集合，並比對 #5 的全部完整反擊集合。超過界限即拒絕完整性聲稱。這確認枚舉完整與重播一致，仍依賴同一 Core 作規則權威。

`--negative-controls` 執行 10 項拒絕案例：錯誤回應數、技能合法性、缺失回應、重複分支、壓掉續局適用性、移除全部續局、重複續局、缺失第二次敵方回合、錯誤終點及錯誤起點。這些 CLI 檢查與 Swift 單元測試數量分開計算；不宣稱所有 JSON 欄位或任意損壞格式都已完整驗證。
