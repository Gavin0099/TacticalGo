# TacticalGo 1.2｜可選兩手試算 × 事件式連鎖成果（產品候選）

**基準：** PR #34 `261154c0a6fd5e7cff1caf4480abd1a4c9ee6dab`。本 Slice 的獨立 Draft PR #40 只做可選的 1.2/Beta 體驗候選，Bot P2 PR #39、P1H 真人試玩 PR #38 皆保持獨立。未合併、未發布、未提交正式規則或付費修改。

## 設計目的與不做的事

讓玩家在正式提交第一手 **之前** 試出合法的第一手與第二手；在未扣資源時理解「棋盤變化、我方／敵方主帥氣、提敵兵、自己犧牲兵、當回合 AP/Mana」。提升確定的事件回饋，不宣稱敵方會如何反擊、不將氣數增加說成永久安全，不把技能表演自動視為較好的選項。

不新增英雄、技能、規則、敵方預告、戰利能力、收費方式或存局 schema；不改 Bot。原有每一步單獨選點、確認、撤銷仍存在。第一手確認後不會自動執行第二手。退出試算只丟棄記憶體的試算結果。

## 職責與資料流

- **TacticalGoContent / `TwoActionForecast`：** 保存開始時完整 `GameState`（含 superko 歷史），以 `GameEngine.apply` 重算完整合法兩手。第一手更改時，第二手若不再合法則清除。結果只讀，不建立 `GameSession`、不發送聲音、不寫檔。
- **iOS / `TwoActionPlanningController`：** 用原有 `TacticalHints.targets` 選棋盤目標，包含 1.1 的技能／進階技能／戰利能力；再次以 Core 判定能否將該手加入試算。玩家可以切換第一手、第二手或完成棋形。
- **現有 `ExpansionBoard`：** 可接受獨立呈現來源，用既有素材畫局面及 Core 結果；當有試算資料時，棋盤點擊只改動試算 Controller，絕不呼叫 live `ExpansionLabStore.select`。
- **現有對局：** 「帶入第一手」先比對 live `GameState` 是否與試算源完全相同，然後只設置選點與 pending action。必須再按原有「確認」才會真正套用、存局、扣資源、播音效。正式第一手成功後，只有當完整 state 與試算後狀態完全相等，才能帶入原先第二手；否則要重試算。第一手已提交後取消規劃**不會**撤銷它。
- **演出：** 現有盜賊連鎖換位的出手、移動、提子音效保持原實作；額外的「提子 ×N」只在真實 Core 收據含敵方士兵被提事件時展示。普通落兵提子也會顯示；無提子則沒有同樣的慶祝動畫。資源／氣數的短文字由正式提交事件算出，不採用測試預測數據。

### 真正的前／後影像比較（Owner 的 macOS / Xcode）

固定 **同一份 7×7 或 9×9 存局、同一 iPhone／iPad、相同語言字級與減少動態設定、相同 Bot policy**；先錄 PR #34 原單手預覽，再錄 PR #40 可選兩手預覽，不要混入研究 Bot。

1. **未提交**：在 2 AP 的局面打開「兩手試算」，選第一手並加入，再選第二手並加入。比較原棋盤、第一手後、第二手後；記錄 AP/Mana、提兵及雙方主帥氣。不按「確認」，關閉：正式棋盤、存局與資源必須無變。
2. **撤回／修改**：第二手已加入後回第一手改點，第二手若變不合法須自動移除；原本合法的第二手則可保留。按「帶入第一手」仍不能觸發正式 Core action；要等本來的「確認」。
3. **連鎖演出**：帶入第一手→原確認→等待落定→帶入第二手→原確認。錄下盜賊連鎖換位的原有動作、收據提子與資訊標示；比較無提子技能以及**普通落兵提子**，確認都依實際事件決定是否顯示「提子」。
4. **戰士與法師**：取已有的合法技能＋落兵局面，檢查試算能說明戰士防守、法師調度，而不是靠新動畫才能看懂。
5. **回背景／易用性**：第一手試算尚未提交時切換前後景、退出／重開；任何情況不得偷偷確定計畫。Reduced Motion 應有靜態結果資訊；正常動態勿遮住棋盤目標或確認鍵。

### 暫定接受門檻

- **基本正確性 Gate**：核心實測、原生 UI 操作、取消及背景返回、原生擴充／原規則分離均無回歸。
- **使用體驗 Gate**：不含提示時，玩家能清楚區分「預覽」「已加入試算」「已正式確認」，以及當回合花 4 能量不等於下一回合剩 3 能量。由使用者觀看同裝置的前後錄影比較，評估資訊是否更好懂、演出是否過長。
- **不能宣稱**：未有真人使用前不能聲稱更好玩；未有真機影片前不能聲稱視覺品質已改善；未進行效能量測前不能聲稱無 UI 卡頓。

## 原生檢查發現的修正（2026-10-24）

空的試算預覽原先會透過 `planning?.preview ?? store.preview`，借用正式對局尚未確認的預覽。因此在正式棋局選 A1、再打開空試算時，會出現不屬於試算的落兵影像。現在先判斷是否正在試算；試算中的空預覽保持為空。未修版的原生回歸確實失敗，修正後通過；關閉仍保留原本單手選點，沒有偷偷提交或消耗資源。

另外補齊試算棋盤與摘要的輔助使用群組，讓格點／摘要能被原生測試與輔助技術辨識；終局顯示「已終局」，不誤稱交棒；只完成一手時不宣稱兩手已完成。這些都只改呈現，不改 Core、存局或 Bot。
