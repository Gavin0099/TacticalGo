# 有證據的自主迭代

適用於已要求的聲畫改善。能自主完成可逆的設計／實作／比較；「對標爐石」不構成無限試驗、額外採購或公開發布的授權。可按使用者指定預算／回合調整，不自行假設 token 上限。

## 比較單位

先保留基線。使用相同的 runtime 尺寸、局面、攝影方向、輸入和結果；音訊 A/B 用相同回放音量或響度匹配，不能把更大聲當作更好。參考影片要記 URL 和取樣時間，實際看過才描述動作；靜態圖片只支持構圖／材質判斷。

每輪只處理可指出的差距，例如面板扁平、主將輪廓被覆蓋、施法和落定缺乏節奏、聲音尖銳。先提出一到兩個有差異的候選，保存原始素材、可編輯來源、參數與最終輸出。不要同輪重畫所有角色、換音樂、改規則，造成無法歸因。

## 三類證據分開

| 類別 | 可檢查內容 | 可以下的結論 |
|---|---|---|
| 工程 | 相同終態、無資源誤扣、事件順序、取消後零舊 cue、素材載入；實際量測的 frame time／混音削波／循環接縫 | 只限已執行的狀態、裝置與量測 |
| 美術／聽感比較 | 畫面層次、材質一致、職業辨識、動作重量、聲音身份、反覆聽的疲勞 | 附具體畫面／音訊和 reviewer 的主觀理由 |
| 玩家驗收 | 不解說能否看懂前後、手機觸控、原版／候選可分辨、連續對局是否受干擾 | 記參與者與情境；不以 agent 自評代替 |

可選的首輪工程目標，例如指定裝置 60fps／約 16.7ms frame budget，或落定音與接觸事件差不超過 50ms，必須先標為本案提案並定義量測方式。平均 FPS、程式排程時間、模擬器錄影、不同步的系統音訊各有局限，不能直接當作真機實測。外部競品沒有公開的數值不要補寫。

## 品質對照表

每項用「改善／持平／退步／未檢查」加證據；不加總成「市場合格分數」。

1. 全畫面第一視線與資訊層級是否清楚，材質與陰影是否一致。
2. 在正常及密集棋局，職業、陣營、主將、目標與危險是否辨識。
3. 操作是否立即有回應，預備／主動作／落定的節奏是否有重量且不拖延。
4. 聲音與可見事件是否配合；次要聲音是否掩蓋關鍵聲音。
5. 同職業的畫面與聲音是否形成同一身份，四職是否有差異。
6. 重播、快速操作、靜音、降低動態及長時間對局是否仍清楚舒適。

對「接近爐石」的判斷必須指明所比較的具體片段和面向。參考頁描述的設計方法、短片印象及完整遊戲體驗是不同證據。

## 繼續或停止

有可重現缺陷或明確比較差距時繼續下一輪，保留前版可回退。建議同一假設連續三輪無可指出的改善就換方法或交出待決；這是避免空轉的預設，不是品質門檻，使用者可調整。

以下情況留下最佳候選與具體缺口：缺少可用 source／所需平台，無法實際播放或檢視輸出，參考方向衝突，或剩餘差異需要偏好選擇。能獨立完成的其他部分繼續做。增加 agent 數量不會自動消除共同審美盲點。

如果使用者明確要求建立持續 Goal，可把已收斂的可驗證目標交給 Goal 功能；不能把一句「市場水準」直接當作可由 agent 自行判定完成的停止條件。Goal 也不等於定時背景工作。

## 本 skill 的下一步示例

「用當前 Owner 指定分支的 runtime 身份製作完整棋盤畫面與魔法之手聲畫的兩個候選。先固定所參考的 Hearthstone／Battlemarked 圖片或片段，保持同一規則／盤面／輸入；比較材質、主次、接觸拍點與可讀性。迭代到已知工程缺陷修完且有可檢視的改善證據，交付最佳候選與未通過的真人／裝置項目。」
