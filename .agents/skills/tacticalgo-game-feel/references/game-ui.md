# 全遊戲介面契約

Owner 已多次要求以爐石的完成度處理整體介面，2026-10-13 特別指出底部仍像一般工具表單。這是持續設計方向，不要每個按鈕、職業或畫面再問一次。

## 共用語言

- 使用有限材料：安靜的灰青桌面、暖木框、霧面技能座、古銅邊與奶油色文字；青色留給可操作或選取，金色留給主要確認、回合與結果。木紋集中於框及棋盤，不把同一深棕紋理鋪滿所有面板。
- 技能是插畫牌：圖像、真實能量費用、名稱、清楚選取底線。第二技能有獨立構圖，II 只是輔助標記；費用由 config 讀取，不能憑記憶寫 3（本輪預設實際為 4）。牧師只有奉獻，不能為排版補出不存在的第二技能。
- 英雄頭像與職業色形成辨識；黑白陣營仍用標記與文字。選取不只靠顏色，不可用仍保留可讀名稱。
- 確認與結束回合分開：確認只有合法預覽可執行；取消／復原有次要層級。預覽不播成功聲、不扣資源。戰利能力要有看得見的入口，不能藏在無提示的橫向滑動外。
- 大廳、資源、操作、結算、教學與支援頁面沿用共用元件。原生 picker／slider／VoiceOver 語義可保留，不能因視覺換皮破壞操作。

## UI20 圖像身份

七技能以清楚的動作關係區分：築壘是雙兵與下壓；重整是戰線與移動弧；魔法之手是單手單兵；雙重牽引是雙手雙兵；換位是兩方交換；連鎖換位是三點；奉獻是己兵向上消散與空座。圖像不能暗示新規則，例如永久城牆、奉獻補兵。

使用 `game-ability-atlas-v20` 的 4×3 等大透明格，保留生成原始像素。生成後先看每格邊界的 alpha，避免下一列圖像漏進上一格；再看 32／48／64px 與實際技能列。七個不同格只證明取樣不同，還要人工看輪廓與操作是否可分辨。

手繪 `game-tray-frame-v20` 只包操作區，中心透明、內緣留出內容空間。技能列的選取線在底緣，不能穿過文字。英雄徽章 44pt；資源保留數字，寶石與 AP 小點為輔助。選角有額外勾選符號，不能只靠邊框色。

## 空間與狀態

- 手機保留目前固定 200pt 操作區，棋盤 frame 由容器決定。Interface 19 使用標頭 44、技能 64、訊息 16、操作 44、三個 4pt 間隔、上下各 10pt。新增資訊先處理層級和揭露，不擠棋盤。
- 所有主要操作至少 44×44pt；375／402pt 都檢查，不只放大圖。四職、法師方向、戰利、對手行動、終局要逐一看。
- 狀態說明可短，但完整拒絕原因與技能說明必須能從說明入口取得。不可只截斷關鍵錯誤。
- 終局用同高結算面板替換技能：清楚勝負、符合歷史的復原、再玩一局。不能留下失效的整排技能，不重複顯示同名主要按鈕。
- 小螢幕、平板橫直向、放大文字、降低動態、灰階、VoiceOver 分開驗證。沒有可用平台就標未驗，不以 browser 固定字體測量推論原生結果。
