# UI-SELL-01｜皇冠戰略：把已有的好玩呈現出來

## 0. 任務定位與執行範圍

Owner 已認為目前核心玩法不錯；本輪優先改善「看起來想玩、操作有回饋、結束後想再來一局」。這不是重新驗證遊戲是否值得做，也不是擴充規則或關卡的任務。

以下是計畫與待執行指令，不是完成紀錄。八個 Slice 是路線圖，不代表同時授權執行。本次只啟動 SELL-00；完成後等待 Owner 選定方向，再逐個啟動後續 Slice。不要同時開多個工作分支、自行合併、發布或改變正式預設。

建議順序：
`SELL-00 → SELL-01 → SELL-02 → SELL-03 → SELL-04 → SELL-05 → SELL-06 → SELL-07`

建議視覺方向：有溫度的英雄桌遊，搭配乾淨、清楚的戰術資訊。這是待驗收方向，不代表新美術已獲核准。保留目前核准的人物、陣營辨識與棋盤語言，讓棋盤成為舞台、英雄成為主角、操作成為有回應的行動。

不要把「遊戲感」簡化成所有元件加金邊、提高飽和度、增加粒子或延長動畫。不要把參考遊戲的塔防、卡牌、養成或解鎖機制搬進來。

## 2. 全部 Slice 共用的 Codex 合約

### 2.1 先鎖定真正的候選基線

先讀專案既有工作指引、目前 worktree、分支、未提交修改與相關變更紀錄。找出 Owner 回報的 iPad「皇冠戰略」1010 對應來源；記錄 commit、額外未提交差異，以及包含的動畫／音效／挑戰功能。不能把遠端 main 當成必然最新，也不能以舊版覆蓋目前候選。

若無法確認 1010 來源，仍可整理參考與不依賴版本的構圖提案，但不得將它們稱為「1010 前後比較」，也不得直接進入正式畫面替換。

保留其他工作的未提交內容。不自動合併 BOT-P2、CONTENT-03、美術分支或其他 PR。不啟動新 AI 實驗或新關卡製作。

### 2.2 本輪能改與不能改

能改：資訊層級、版面、現有元件視覺、導覽呈現、文案清晰度、既有事件的視聽回饋時序，以及必要的薄型 UI 接線。

不能改：Domain 規則、AI 決策、AP／Mana 成本與上限、技能效果與可用條件、主將勝負、英雄重召限制、先後手規則、存檔格式與既有進度語意。不能把 R3 候選技能升格為原版或預設。

不新增：英雄、第二技能、裝備、養成、經驗值、獎勵貨幣、星等、排行榜、每日任務、關卡解鎖、成就、廣告或付費。名稱、Logo 與 App icon 不在本輪重設範圍；先沿用核對後的現有候選。

不重寫已核准的角色動畫與三職特效。需要新插圖或新特效才能成立的畫面，先列素材需求並停在該局部，不用不相干素材冒充完成品。

### 2.3 真實狀態與安全性

顯示的技能名稱、說明、消耗、禁用原因與預覽必須對應正在運行的規則版本。不得為了 UI「比較好看」硬編技能效果、可用性或危險判定。

預覽不提交、不扣資源。成功回饋只能由已接受的 Core／Domain 結果觸發；取消、非法操作不得播成成功。不得由動畫完成 callback 再提交一次動作，或讓背景恢復、重建 View 造成重複音效／扣費。

不新增超出原有資訊能力的「最佳走法」「必死提示」或電腦思考內容。危險提示只能重新呈現基線已有資訊；新增判定能力必須另案。

保留合法性、預覽、確認、取消、復原、重試、存局、棋譜、續玩、退出確認與完成鎖定等原有語意。把進階入口收進次層選單，不等於刪除功能。

### 2.4 平台、閱讀與節奏

iPad 是主要視覺驗收裝置，但每個可玩 Slice 都要同步檢查一款專案支援的最小 iPhone，不能最後才發現排不下。保留基線支援的橫直向，不擅自鎖定方向。

一般按鈕命中區至少 44×44 pt。棋盤交點不得藉由互相重疊的透明區域假裝達標；小螢幕要驗證相鄰點選擇，並保留既有大按鍵選點等替代操作。

陣營與狀態不能只靠顏色辨識。保留文字／圖形提示、可讀對比、無障礙標籤與既有輔助操作。增大系統文字時，不得裁切主要按鈕或關鍵資源。

保留 Reduce Motion、靜音與聲音偏好；英文語音維持關閉，除非 Owner 另有指示。iPad 沒有觸覺回饋時仍須有完整的視覺與聲音回應。

裝飾動畫不可增加人工等待或吞掉輸入。核心棋局提交與動畫呈現分離；該擋的重複／非法操作仍要擋。不得以「讓人以為 AI 更厲害」為由增加假的思考時間。

### 2.5 每個 Slice 的交付

只交付本 Slice 的候選與簡短證據：base/head、改了什麼、未改什麼、同裝置／同局面的前後比較、實際測試結果、未驗證事項、回復方式。

沿用既有測試與紀錄機制，不建立新的大型驗收框架。測試項目依變更範圍選取；不得沿用歷史通過數當成本次結果。

靜態設計圖、模擬器、實機錄影與後製音訊分開標記；不能用宣傳合成圖替代可玩介面證據。技術通過、Owner 主觀體驗通過、廣泛使用者驗證是不同狀態。

依專案慣例保存獨立候選／Draft PR，不自動合併、送審或發布。遇到本 Slice 以外缺口先列出，不順手擴案。

## 4. 可逐段交付的 Slice 指令

### SELL-00｜現況、參考與視覺方向

```text
執行 UI-SELL-01 / SELL-00，遵守全部共用合約。

先核對 iPad 1010 的實際來源與已核准素材。盤點大廳、選角、
對局、技能預覽、結算與六關入口；能取得的用同一候選原生畫面，
不能取得的明列，不以舊截圖冒充最新版。

研究指定三款參考遊戲，總計選最多六張真正有用的圖片。
每張只寫：看見什麼、借用哪個具體原則、不借用什麼。
不研究其商業模式、關卡設計或角色養成。

使用現有角色與棋盤，做一組推薦方向：
1. 一張完整對局畫面，含真實棋盤比例、資源與操作區。
2. 一張大廳畫面，含主要開局／續玩入口與次要入口。
兩張應屬同一套視覺語言，不做十種風格海選。

用 iPad 原尺寸評估，再補最小支援 iPhone 的排版確認。
可做隔離且可丟棄的 View Preview 或構圖稿；不替換正式導覽，
不修改玩法、AI、素材身份或目前候選的正式畫面。

交付現況／候選比較、來源記錄與下一 Slice 的具體改動清單。
完成後停止，等 Owner 判斷「這個方向是否更想玩」。
不得自行開始 SELL-01。
```

### SELL-01｜先做一個真的能玩的對局畫面

```text
前提：SELL-00 視覺方向已獲 Owner 選定。
只執行 SELL-01，不擴到整個 App。

以現有棋盤、角色與操作流程製作可玩的新版對局畫面。
整理為：回合／雙方資訊、棋盤主體、目前行動與操作區。
iPad 寬畫面可把操作放側邊；小螢幕採上下配置，
不得為裝飾擠小棋盤、改變交點幾何或遮住主將與合法落點。

AP／Mana 讀取真實狀態；技能操作顯示圖示、名稱、消耗，
不能只剩華麗圖示。可用、已選、禁用及禁用原因要分清楚。
一般落子、技能、確認、取消、結束回合不能互相混淆。
不新增每次普通落子都要多按一次的流程。

共用字級、間距、面板與按鈕樣式，只抽取本畫面需要的內容；
不把本 Slice 變成沒有玩家可見成果的 Design System 專案。

用同一合法棋局比較舊版與候選；展示普通落子、技能預覽、
取消、不足資源、敵方回合等狀態。完成一段真實攻防操作。
驗證相鄰交點、選取偏移、文字大小與按鈕命中，
保留既有輔助選點與確認／取消語意。

交付可玩候選、同尺寸前後截圖與短錄影。
驗收重點：更有遊戲感，但資訊辨識與操作沒有退步。
```

### SELL-02｜操作回饋與三職節奏

```text
以前一 Slice 為基線，只整理現有事件的回饋，不重做三職美術。

梳理選中、預覽、確認、行動成功、提子、資源變化、
回合切換與主將危險的可見回應。一般落子要俐落；
技能與提子有較明確節奏，但不能每次都全畫面震動或遮棋盤。

沿用已核准動畫／特效與音效，調整 UI、角色、棋子結果的銜接。
同一成功事件只呈現一次；預覽、取消、非法動作不得播成功效果。
復原或歷史重播不得被誤當新獎勵，快速點擊不重複提交。

測一般行動、三職技能、無提子／有提子、取消、復原、
快速連點、轉向、切背景及 Reduce Motion。
不得以增加輸入鎖定時間換取動畫完整。

用正常速度實機或模擬器原生錄影比較，不靠剪輯加速／後製音效
掩蓋實際等待。標示音訊來源，聲音偏好不得被重設。
驗收重點：每次操作有回應，連下數手仍然俐落。
```

### SELL-03｜大廳：讓人自然開始玩

```text
只改大廳與現有入口的資訊層級，不新增遊戲模式。
沿用 SELL-00 核准方向與 SELL-01 的共用樣式。

有可續玩的存局時，優先顯示「繼續戰局」；
沒有時，以「開始對戰」為主要入口。依實際存局狀態判斷。
挑戰與學習入口保持易見；音訊設定、棋譜、進階對局設定
放次層但保留功能，不把尚有用途的入口直接移除。

主要入口不用翻完整頁設定才能找到。
一般玩家沿預設設定開新局，目標不超過三次主要點擊；
這是設計目標，不得因此默默修改模式、難度、陣營或規則預設。

不得在有存局時直接覆寫，不擅自變更退出／另開新局語意。
不加強制開場影片、假活動、每日獎勵、排行榜或商店入口。

測無存局、有存局、無法續玩的資料、返回大廳與另開新局。
交付原生大廳畫面與從開啟到開局的完整操作錄影。
驗收重點：第一眼知道下一步，也看得到英雄桌遊的主題。
```

### SELL-04｜選角：角色感與技能真實性

```text
只重整現有選角，不新增英雄或技能。
保留現有職業、陣營與規則選擇能力。

每位英雄使用核准原畫、名稱、清楚的技能摘要與選取狀態。
放大人物存在感，但不能用大圖把開始按鈕擠出畫面。
點選有短回應；取消與換角色不消耗正式戰局任何資源。

說明、消耗與展示必須對應所選的原版／候選規則。
不使用攻擊力、防禦力、星等、稀有度等不存在的數值。
定位文案不得把候選效果說成原版效果。

技能展示優先重用已驗證範例或既有預覽能力，
必須與正式 GameStore／存檔隔離；不能為了選角展示另寫規則。
若現有基礎不足，先做靜態摘要，不偷偷擴出完整互動教學。

本機雙人與電腦對戰都要看得懂目前在替誰選擇。
交付三職、黑白方與規則切換的畫面／操作證據。
驗收重點：想選這個角色，且知道真正選到的能力。
```

### SELL-05｜勝負結算與再玩一次

```text
只改善已存在的勝負呈現與下一步操作，不改勝負判定。

從既有 Domain 結果讀取勝利、失敗及任何既有其他終局狀態，
使用與棋盤一致的結算面板，保留終局棋形的視覺脈絡。
不要用不存在的分數、戰力、經驗值、獎盃或 AI 精彩評語填版面。

一般對局提供再戰與回大廳；挑戰依既有可用狀態提供重試、
下一關與返回。不能硬套同一組按鈕造成不存在的下一關。
再戰沿用既有新局流程與設定，不是把舊存局原地清掉。

結果只顯示一次，終局禁止繼續落子；重複點擊、旋轉或
切背景不得重複結算、重複開局或遺失舊紀錄。
保留退出／覆寫等破壞性操作所需的確認，不為遊戲感移除。

交付真實成功、失敗、重試／再戰的短錄影。
驗收重點：情緒有收束、看得懂結果，下一局不用繞選單。
```

### SELL-06｜把現有六關包成清楚的挑戰內容

```text
只重整現有挑戰目錄，不新增第七關、不開第二章，
不與 CONTENT-03 混成同一份變更。

以六張簡潔關卡卡片或一致的章節版面，顯示關卡名、
既有目標摘要與真實完成狀態。可用既有合法盤面作小預覽，
不能用標題或縮圖直接把完整解答告訴玩家。

完成紀錄取現有來源，未完成、已完成與可重試要清楚。
沒有星等、最佳步數或解鎖系統，就不假造這些資訊。
不為了像手遊而製作大型世界地圖或裝飾性長路徑。

保留原提示、重試、復原、退出與續玩功能。
完成六關後仍容易挑選任一關重玩，不強迫依順序再走一次。

驗證進度不變、資料隔離不變、不同螢幕無按鈕裁切。
交付六關目錄、未完成／已完成與重玩流程的原生證據。
驗收重點：容易選內容，而不是靠虛構獎勵營造完成感。
```

### SELL-07｜完整體驗與候選交付

```text
只整合已獲核准的前序 Slice，不重新發明視覺方向。
核對來源與依賴，不把尚未核准分支一次全部合進來。

以同一候選走完整流程：
```

## 5. 體驗驗收準則

以下是本輪設計目標，不是已量測的成果，也不是市場成功保證。

- 想開始：不讀操作說明，短暫看大廳即可指出主要入口；沿預設流程能迅速進局。
- 想操作：看得懂輪到誰、還能做什麼、技能為何可用／不可用；操作有回應而不拖慢。
- 想再玩：結果清楚，重試／再戰自然；不是被獎勵、假進度或強迫動畫留下。

Owner 認為方向不對時，先在小範圍修改，不把未獲認可的樣式鋪滿所有畫面。單張圖片漂亮不足以通過互動驗收；全數自動化測試通過也不足以宣稱更好玩。
