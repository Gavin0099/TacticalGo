| 戰術事件辨識 | 有預覽、提子、主將危險與法師／怪物機制 | 須避免大範圍閃光蓋住棋盤、主將與氣 | 中：邏輯可查；實測待補 |

### 優先修正的實際視覺症狀

1. **材質統一：** 桌板有紋理，四周卡片和行動區仍顯得扁平；需要同一光源、邊緣高光、接觸陰影與材質用量，而非每個面板各畫一種質感。
2. **盤面主從：** 直向螢幕的表頭、狀態列與下方控制占掉視覺焦點；不能一味放大角色而蓋住棋盤交叉點，應先做焦點與局部事件強化。
3. **對比與回饋：** 次要說明、disabled「確認」、選取圈及資源數值的明暗差不足；需在 7×7／9×9 正常和密集局面都可辨識。
4. **聲畫動作：** 語音、施法、推動、接觸、提子、收勢要在一條成功事件時間軸對上；靜音／取消／復原仍不能留下殘影或過期語音。

## 3. 開發切片（不得重做已存在的 UI20／動畫候選）

### P0｜PRES-00：凍結 1106 原生 A/B 基線與來源比對

**依賴：** 無。**先執行。**

- 建立 source mapping：TestFlight build `1.1(1106)` → 對應 `e25b2d8` 原始碼；比較 `codex/v11-game-interface` 最新候選差異（UI20、animation-24、Skill1.7），逐項標註未進入 1106 的內容。
- 用同一固定棋局、相同裝置、同一套操作，取得正常速度、**含原始裝置音訊**的 1106 影片：開局→選取／預覽／取消→兩次操作→法師魔法之手／戰士築壘→提子→主將危險→勝負，以及雙怪／戰利示範。
- 每份紀錄包含設備、iOS、棋盤大小、build、分支、素材版本、時間碼。截圖不能取代動畫，後製音效不能冒充真機混音。
- **驗收：** 完整基線表與缺口清單、真機影片或明示未取得原因；新的候選不可混入 baseline。

### P1｜UI-21：整合材質、版面與狀態層級

**依賴：** PRES-00。**優先重用 UI20，禁止不查來源就重畫。**

- 檢查 UI20 已核准的範圍並與 1106 對照，將確有改善的桌板材質語言延伸到角色卡、狀態列、行動卡和按鈕。
- 提升回合、AP/Mana、選取／合法目標／確認／不可用的視覺權重，避免三個相似的淡色文字卡片。
- 7×7／9×9、375／402 pt 及小尺寸比較；不得犧牲棋子歸屬、主將危險、格點或觸控範圍。
- **驗收：** 相同場面新舊 native 截圖 A/B；首眼可說出輪誰、正在選哪格、下一步能做什麼；版面不跳動；不把 browser mockup 當實機證據。

### P1｜ANIM-25：一套完整的職業施法動作（先法師＋戰士）

**依賴：** PRES-00。可與 UI-21 平行開發。

- 優先使用 1106 中現有 `ExpansionPresentation`、`ExpansionSpellEffects`、法師／戰士姿勢元件，以及 animation-24 候選，不另造第二套規則。
- **法師：** 法杖蓄勢→指向目標→魔法移子→接觸→頭／披風收勢；**戰士：** 盾後拉→快速下擊→接地停頓→回彈。動作不能只剩圖片放大與發光。
- 普通技能朝 **0.6–0.9 秒**候選驗證，真正終局高光可另設較長；這是 UX 提議，不是《爐石》官方參數。兩 AP 連續行動不得感覺一直在等。
- **驗收：** 同棋局、同速度原生影片 A/B；10 次連續出手仍自然、角色／棋盤資訊不被蓋住；時間軸無狀態回退；取消／Undo／新回合清乾淨；失敗行動不播成功效果。

### P1｜AUDIO-25：職業聲音身份、材質 SFX、語音與音樂混音

**依賴：** PRES-00。可與 ANIM-25 平行製作，最終由同一時間軸同步。

- 沿用現有法師英文 B、戰士英文 B 作對照；盜賊與牧師的 A/B 演技候選另行盲聽，不因 B 是預設就當核准。
- 設定「召喚／施法／接觸／提子／勝敗」不同優先權；角色語音稀疏出現，避免每次施法重複同一句。
- 音效使用物理材質（盾／木／布／魔法／史萊姆／狼），不只是音調改變；做等響度 A/B，並核對 BGM duck、語音被 SFX 蓋住、重疊削波與音訊中斷。
- **驗收：** dry voice／mix 分開存、音效 stem 與權利來源表、iPhone 喇叭／耳機真機錄音、盲聽紀錄；安靜與連續對局各能清楚聽到主要事件，無突兀爆音或重複台詞疲勞。

### P1｜SYNC-25：單一已確認事件的聲畫時間軸

**依賴：** ANIM-25、AUDIO-25。

- 將 1106 既有演出排程整合為單一 receipt/事件驅動的 presentation director；動畫、SFX、voice、震動均綁定正式 Domain outcome 和可取消 session token。
- 不允許視覺動畫、計時器回呼和聲音自行判斷提子、資源或勝負。預覽、成功、失敗與減少動態的語義一致。
- **驗收：** 接觸畫格與主要命中音目標差距不超過 **50ms（提案值，需裝置量測）**；快速連打、復原、重開、前景切換、Bot 晚回覆、靜音、減少動態均不殘留。

### P2｜ANIM-26：四職業／第二技能／怪物的覆蓋矩陣

**依賴：** ANIM-25、SYNC-25、UI-21。

- 擴充盜賊換位／連鎖換位、牧師奉獻及職業第二技能；逐技能指定 **預備形狀、移動軌跡、接觸方式、殘留標記與音色**。
- 史萊姆黏彈、暗影狼影步、討伐與戰利取得／使用，做短而有角色感的演出；討伐與英雄主將的勝負層級不得混淆。
- **驗收：** 實際程式行動矩陣完整（以目前 1106 可操作選項為準），每個技能都有「預覽／成功／非法／中斷／減少動態」；原生完整片段、7×7／9×9 密集局可讀。

### P2｜POLISH-27：結果高光與整局節奏

**依賴：** UI-21、ANIM-26。

- 單獨處理提子、主將被提、回合交換、獲勝／落敗、取得戰利的情緒節點；只有大事使用較長鏡頭／額外音樂句，不讓普通放子變成大型過場。
- 調整短操作可跳過／不阻斷下個合法行動，避免每回合兩次操作造成疲勞。
- **驗收：** 第一次看懂事件、連續三局不煩躁、終局可辨認；與 1106 相同合法重播盤面及資源完全一致。

### P0→P2 全程｜QA-28：可發 TestFlight 的品質門檻

**依賴：** 每個 slice 都要執行相關項目；最終 Gate 必須一次驗收。

- 功能：既有 Swift／Golden／UI 回歸保持綠燈，不把历史通過冒稱新版本全套；兩棋盤尺寸、雙人、Bot、四職、技能、怪物、存局、Undo、AI 非同步中斷。
- 畫面：小／大螢幕、正常／密集局，確保棋盤 anchor、點選區、主將／陣營／危險、色彩與字級辨識。
- 聲音：喇叭／耳機、靜音／語音關閉、背景前景、音效重疊、實際音畫同步。
- 效能：真機測 P95 frame time；若以 60fps 為目標則 16.7ms 為每幀預算；量測後依裝置訂容許範圍，不假稱已達標。
- 真人：至少 3 位沒有被事先提示技能效果的試玩者；測「看得懂、聽得清、想再玩、哪些動畫太長」。它是回饋而非統計上的市場認證。
- **驗收：** 將工程 PASS、實機 PASS、獨立視聽評審、Owner 核可各自註記；無 Owner 授權，不上傳新的 TestFlight、不併 main、更不公開 App Store。

## 4. 順序／停止條件

```text
PRES-00 ──┬── UI-21 ───────────────────┐
          ├── ANIM-25 ──┐             ├── ANIM-26 ── POLISH-27
          └── AUDIO-25 ─┴── SYNC-25 ──┘
                   QA-28 貫穿每個 slice → 最終 TestFlight 候選 Gate
```

- **首個決策點：** PRES-00 + UI-21 + ANIM-25 + AUDIO-25 的第一組可播放 A/B，即先判斷是否真的更接近目標，不要一次把所有職業特效重做。
- **避免假成功：** 固定錄影可比／改善可指出，才升下一片；若三輪相同改善假設仍無具體進步，退回最好候選、換方法，並保留不過門的證據。
- **不以「90% 爐石品質」作機器 Gate：** 動畫、聲音、美術是不同度量；以比較片段、盲審及使用者體驗做決定。
